# ADR-0005: Benchmark data sources, containers and autovacuum

**Data sources.**
- TPC-H SF1 is generated by DuckDB's official `tpch` extension (`dbgen(sf=1)`), installed from PyPI at a pinned
  version (`bench/spike/requirements.txt`). The canonical tpch-kit `dbgen` was not built here: it runs downloaded
  code, and the owner asked for no such run outside a reviewed disposable container.
- JOB uses the May 2013 IMDb CSVs (https://event.cwi.nl/da/job/imdb.tgz, 1.26 GB, archive listed before extraction:
  21 CSV files and one SQL file). The schema and FK indexes come from https://github.com/gregrahn/join-order-benchmark
  (`schema.sql`, `fkindexes.sql`). Only SQL is executed, through psql.
- Query texts are used unchanged (DuckDB `tpch_queries()` for TPC-H, the JOB repo for JOB).

**Containers.** Benchmarks run in containers built from the local `plantwin-postgres:18` image. Autovacuum is
disabled with `-c autovacuum=off`.

**Why autovacuum off.** The first JOB run was unstable. Autoanalyze ran on the populated database while the pipeline
was dumping stats, so the clone and the populated plans came from different snapshots. `ANALYZE` is run explicitly
at the start of each pipeline run instead.

**Noise.** `ANALYZE` samples rows at random. Results are reported as two independent runs, with the run-to-run
variation shown next to the fidelity numbers (`bench/results/*/noise_*`).
